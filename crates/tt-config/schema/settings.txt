# The settings schema.
#
# One line per setting, and `src/bin/gen-settings.rs` turns the file into
# `src/generated.rs`: the struct, the defaults, the reader, the writer, and a
# metadata table that the dialog, the scripting commands and the docs all walk
# instead of each carrying their own copy of this list. `PLAN.md` calls that
# the difference between the project finishing and not — `common/tttypes.h` is
# a 909-line struct surfaced by ~13.8k lines of dialog code across 76 templates,
# and hand-porting it is where the motivation goes to die.
#
#   name | type | section | key | default | label [| option...]
#
# `name` is dotted: the part before the first dot is the dialog page, and the
# whole thing is what a script says. It becomes a Rust field with the dots
# turned into underscores.
#
# `label` is the `.lng` key for the dialog, or `-` where upstream has no dialog
# for it. Those are real settings people set by hand, so they still need to be
# readable and writable — they just have no widget yet.
#
# The optional `write-if` is for a key upstream reads but conditionally omits
# when it saves. It names another boolean setting. Leaving the old line alone
# when that boolean is off matters: deleting it or writing a default would
# change a shared `TERATERM.INI` that the user did not ask this program to own.
# `write-key=Key` records the one upstream reader/writer mismatch. A key **or a
# default** may be enclosed in backticks when leading or trailing whitespace is
# significant; the backticks are schema punctuation and are not part of the
# value. Both fields are trimmed otherwise, so a value like the proxy's
# `` `>> Host name: ` `` — whose trailing space is what makes it match a prompt
# rather than a prefix of one — has no other way to be written down.
#
# `default-from=name.of.int` is the other optional field. It reproduces a key
# whose fallback is another setting's already-loaded value rather than a
# constant. Both fields must be scalar integers. The constant default remains
# the value used when neither key exists and the value shown in metadata.
#
# Types:
#   bool          `GetOnOff`, which is **not** a symmetric parse. See below.
#   int           `GetPrivateProfileInt`
#   int(lo..hi)   ...bounded the way `ttset.c` bounds one: **below `lo` takes
#                 the default, above `hi` takes `hi`.** Not a clamp in both
#                 directions — `TerminalSize=0,0` is 80x24, not 1x1. The pair is
#                 also what the dialog builds a spin box from.
#   int(lo..)     the same with no ceiling, which is how `MaxBuffSize` is read
#                 (`ttset.c:1214`) — upstream caps that one against a
#                 compile-time constant in `buffer.c` rather than on the way in
#   int_zero      a comma-separated field read through `GetNthNum`: an absent
#   int_zero(...) *key* takes the default, but a missing or empty field in a
#                 present value is zero. `VTPos=12` is `(12,0)`. Plain `int`
#                 fields use their own default there instead, which is what
#                 the transfer timeouts' different helper, `GetNthNum2`, does
#   int_clamp(lo..hi)
#                 clamped at **both** ends, `min(max(lo, v), hi)`. The third of
#                 three bounds and a special case of neither: `int(lo..hi)`
#                 would give the default below the floor, `int_min(lo)` has no
#                 ceiling. Only `PasteDelayPerLine` is read this way
#   int_default(lo..hi)
#                 outside either end takes the default. Unlike `int(lo..hi)`,
#                 a value above the ceiling is not capped; the Unicode width
#                 settings accept only 1 or 2 and take 1 for everything else
#   int_alias(word=n)
#                 an integer with one textual alias recognised first. The
#                 writer emits the resulting number; `MaximizedBugTweak=on`
#                 therefore reads as 2 and writes back as `2`
#   uint16        `GetPrivateProfileInt` assigned to a `WORD`: modulo 65536,
#                 then written back unsigned. `TitleFormat=-1` is 65535 and
#                 `TitleFormat=65537` is 1
#   string        the raw value
#   enum(...)     `spelling=Variant`, compared case-insensitively (`_stricmp`,
#                 which is what upstream uses for all but one of these);
#                 anything that matches nothing takes the *default*, which is
#                 how upstream spells most of its defaults and why several of
#                 them are an `else` branch rather than a value. A spelling of
#                 `*` overrides that: it names the variant an unrecognised
#                 value takes, for the one setting whose `else` and whose
#                 default are **not the same arm** — see `window.title_change`
#   enum_exact()  the same, compared with `strcmp`. Only `TerminalID` is, and
#                 the consequence is that a lower-case spelling reads as the
#                 default instead of failing
#   color2        two RGB triples, `fg_r,fg_g,fg_b,bg_r,bg_g,bg_b`
#
# **`GetOnOff` is default-biased** (`ttset.c:344`) and this is a trap worth
# stating twice. With a default of on, anything that is not literally `off` is
# on; with a default of off, only literally `on` is on. So `Key=1` means
# *different things* for two different settings, and `Key=yes` means off for
# half of them. It also reads into a 4-byte buffer, so only the first three
# characters are compared and `offline` is `off`. All of it is reproduced.
#
# Comment lines immediately above a setting become its developer documentation.
# Cite the line in `ttset.c` that proves the default — `AGENTS.md` has four traps
# that are all "the default is not where it looks like it is".
#
# Lines that start with `#@` become the setting's user help. Explain what the
# setting changes and when it is useful. Do not expose source names, internal
# fields or implementation details there.

# --- terminal ---------------------------------------------------------------

# `ttset.c:615`, bounded by `TermWidthMax` — which is **1000**, not the 500
# this used to say; 500 is `TermHeightMax`, the next line of `tttypes.h:633`.
# Zero or less takes the default rather than the floor, which is what the range
# means here.
#@ This setting sets the terminal width in character columns. A larger value gives remote programs more horizontal space.
terminal.cols | int_zero(1..1000) | Tera Term | TerminalSize.1 | 80 | DLG_TABSHEET_TITLE_TERM

# `ttset.c:619`, the second half of the same key, bounded by `TermHeightMax`.
#@ This setting sets the terminal height in character rows. A larger value shows more output without scrolling.
terminal.rows | int_zero(1..500) | Tera Term | TerminalSize.2 | 24 | DLG_TABSHEET_TITLE_TERM

# `ts.TerminalID`. `ttset.c:709` reads the key with an empty default and hands
# it to `TermIDGetID`, which is a case-sensitive `strcmp`
# (`tttypes_termid.cpp:60`) against the table above it, returning `IdVT100` for
# anything it does not recognise — so it never fails, a typo silently runs as a
# VT100, and so does `TerminalID=vt320` in the wrong case. The one enumerated
# setting here that is not `_stricmp`, hence `enum_exact`. Note `dumb` is
# lower-case in upstream's own table while every other spelling is upper.
#@ This setting selects the terminal model for behavior and capability replies. Each name is case-sensitive. An unknown name selects VT100. The selected model must agree with the model that the host expects.
terminal.id | enum_exact(VT100=Vt100,VT100J=Vt100J,VT101=Vt101,VT102=Vt102,VT102J=Vt102J,VT220=Vt220,VT220J=Vt220J,VT282=Vt282,VT320=Vt320,VT382=Vt382,VT420=Vt420,VT520=Vt520,VT525=Vt525,dumb=Dumb) | Tera Term | TerminalID | VT100 | DLG_TERM_TERMID

# **`ttset.c:631`, and upstream's default is the `else` branch.** A bare CR is
# a carriage *return*, not a newline, so `"Hello\rWorld"` overwrites the line.
# `AUTO` is upstream's fourth value (`vtterm.c:727`, 2012) and is reproduced
# exactly: it takes a bare CR *and* a bare LF as whole line endings for ever,
# which puts every prompt redraw an interactive shell makes on a line of its
# own. `DETECT` is Sterna's own and is what ships (deviation 9): the first line
# ending decides which of the three the far end means and the terminal is that
# exact mode from then on, so a serial device needs no first session to discover
# its spelling and a host still gets its cursor motions. Every upstream
# spelling, `CRReceive=CR` included, remains byte-for-byte compatible; Tera Term
# reads `DETECT` as the unrecognised value it is, which is its own `CR` default.
#@ This setting controls how received carriage-return (CR) and line-feed (LF) bytes create new lines. Detect selects a mode from the first LF and keeps a standalone CR as cursor movement.
terminal.cr_receive | enum(CR=Cr,CRLF=CrLf,LF=Lf,AUTO=Auto,DETECT=Detect) | Tera Term | CRReceive | DETECT | DLG_TERM_CRRECEIVE

# `ttset.c:646`, the same shape, one variant short — there is no AUTO on send.
#@ This setting selects CR, CRLF, or LF for carriage-return output from terminal input.
terminal.cr_send | enum(CR=Cr,CRLF=CrLf,LF=Lf) | Tera Term | CRSend | CR | DLG_TERM_CRSEND

# `ttset.c:660`.
#@ This setting shows typed characters locally without an echo from the remote host.
terminal.local_echo | bool | Tera Term | LocalEcho | off | DLG_TERM_LOCALECHO

# **`[Sterna]`**, because this is a local editor rather than telnet LINEMODE
# (`connection.line_mode`). While enabled, printable keyboard input is held in
# the terminal view until Return sends one edited line. Local echo is effective
# for that send without overwriting `terminal.local_echo`, so leaving the mode
# restores the user's preference. Off by default: an ordinary terminal remains
# immediate unless the user explicitly opts in.
#@ This setting edits printable input locally until Return sends the line. Backspace, Delete, selection, and usual editing shortcuts also stay local. Other keys send immediately.
terminal.line_edit | bool | Sterna | LineEdit | off | -

# **`[Sterna]`**. A painter-only dark palette for the terminal grid and its
# local line editor. It deliberately does not change QApplication's palette:
# menus, dialogs, toolbars and status bars remain the desktop theme. The
# connect bar persists the switch immediately and applies it to every tab.
#@ This setting uses a dark palette for terminal content and its line editor. Menus, dialogs, and other application controls keep the desktop theme.
terminal.dark_mode | bool | Sterna | DarkMode | off | -

# **`[Sterna]`**. A column of line numbers down the left of the terminal.
#
# The number is the absolute session line, counted from 1: line 1 is the first
# line the host printed, and a line keeps its number as it scrolls into
# history. The gutter is painted by a widget beside the terminal rather than
# into it, so the numbers are not cells and cannot reach the clipboard, the
# log, the printer or a macro's tap.
#@ This setting shows line numbers in a column at the left side of the terminal. The first line from the host is line 1, and a line keeps its number in the scrollback. The numbers are not terminal content. Sterna does not include them in a selection, the session log, the printer output, or macro text.
terminal.line_numbers | bool | Sterna | LineNumbers | off | -

# **`[Sterna]`**. How many digits the gutter above reserves.
#
# Fixed rather than sized to the largest number on screen, so the terminal
# never re-flows mid-session at line 1000; a number that does not fit is left
# blank rather than clipped, because the column is at the window's left edge
# and a clipped `10001` reads as `0001`. Six because the number a session
# reaches has no ceiling — four is a few minutes of `cat`. `int_clamp` and not
# `int(1..10)` because there is no upstream reader to reproduce here, and
# clamping is the predictable answer where `ttset.c:615` would take the default
# for anything below the floor.
#@ This setting sets the number of digits in the line-number column. The width stays the same for the full session, because a change would move the terminal. A line with a longer number has no number. Values use 1 thru 10.
terminal.line_number_width | int_clamp(1..10) | Sterna | LineNumberWidth | 6 | -

# `ttset.c:625`. With it on, resizing the window resizes the terminal.
#@ This setting stores Tera Term's option for resizing the terminal with its window. Sterna always fits the terminal to its view. Thus, this setting has no effect.
terminal.size_follows_window | bool | Tera Term | TermIsWin | off | DLG_TERM_TERMISWIN

# `ttset.c:628`. With it on, a remote resize resizes the window.
#@ This setting stores Tera Term's option for remote terminal-size requests. Sterna handles supported remote resize requests even if this setting is off.
terminal.auto_win_resize | bool | Tera Term | AutoWinResize | off | -

# `ttset.c:1676`, part of `TermFlag` — the same trap as `ColorFlag`. Whether
# changing the terminal's size scrolls the page away and homes the cursor.
#
# Off, so the screen survives a resize and what moves is which lines the page
# covers (`buffer.c:5001`). Two things it does that its name does not say:
# with it **on** the clear happens even when the size did not change, because
# `BuffScroll` sits outside the `if (size changed)` block (`:5028`); and
# DECCOLM tests it and skips its own clear, since `ChangeTerminalSize` has
# already done one (`vtterm.c:2925`).
#@ This setting clears the displayed page and homes the cursor each time Sterna applies terminal size. It can also clear the page if the size does not change.
terminal.clear_on_resize | bool | Tera Term | ClearOnResize | off | DLG_TAB_GENERAL_CLEAR_ON_RESIZE

# `ttset.c:1444`. Whether `ED 0` with the cursor already at the home position
# is treated as `ED 2`.
#
# **It is not the gate on `ED 2` its name suggests.** `CSScreenErase`'s `case 2`
# calls `BuffClearScreen` whatever this says (`vtterm.c:1740`), and a clear
# screen is a scroll into the history rather than an erase either way; what
# the key decides is only whether the `ESC [ H ESC [ J` pair — which many
# programs send in place of `ESC [ 2 J` — takes that path too. Turning it off
# leaves those programs erasing to the end of the screen, which is what the
# sequence literally asks for and loses the screen out of the history.
#@ This setting treats a move home followed by erase-to-end as a full screen clear. The clear moves the old page into scrollback.
terminal.home_erase_clears_screen | bool | Tera Term | ScrollWindowClearScreen | on | -

# `ttset.c:743`. Off keeps the terminal to one screen and no history.
#@ This setting keeps lines that scroll off the page in view. The off value keeps only the current screen.
terminal.scrollback_enabled | bool | Tera Term | EnableScrollBuff | on | DLG_TERM_SCROLLBUFF

# `ttset.c:751`. Upstream ships **100** lines, which is small for a console
# log; it is a setting rather than a constant precisely so it can be raised.
#@ This setting sets the total number of lines when scrollback is on. The total includes the page in view. A value no larger than the page gives no scrollback. A larger value gives more history.
terminal.scrollback_lines | int | Tera Term | ScrollBuffSize | 100 | DLG_TERM_SCROLLBUFF

# `ttset.c:1212`, and upstream's comment on it is "special option" — there is
# no dialog. It is the ceiling `ScrollBuffSize` is held under, not a second
# depth: `buffer.c:511` caps the buffer's line count with it and `:4977` caps
# the *terminal's row count* with it too, so `MaxBuffSize=10` is a ten-row
# terminal however big the window is. Below 24 takes the default rather than
# the floor, which is the `TerminalSize` bound with no ceiling on it.
#@ This setting sets the maximum total buffer size and terminal row count. Values less than 24 use the default.
terminal.buffer_max_lines | int(24..) | Tera Term | MaxBuffSize | 10000 | -

# `ttset.c:1875`. Which ISO-2022 shifts the terminal honours, as a
# comma-separated list — `SI`, `SO` (`LS0` and `LS1` are read-only aliases for
# those two), `LS2`, `LS3`, `LS1R`, `LS2R`, `LS3R`, `SS2`, `SS3` — each
# optionally led by `+` or `-`, plus `on`/`all` and `off`/`none`, which assign
# the whole word rather than one bit.
#
# A `string` rather than a type of its own: it is the only key in `ttset.c`
# shaped this way, and `ShiftFlags::parse_ini` already lives beside the bits it
# names. **The list starts from nothing whatever this default says** — the
# `"on"` is what upstream uses when the key is *absent*, and a key that is
# present starts at `ISO2022_SHIFT_NONE`, so `ISO2022ShiftFunction=-SS2` is a
# terminal with every shift disabled rather than all but one.
#@ This setting selects accepted ISO-2022 character-set shifts. The on and all values select all shifts. The off and none values select no shifts. A custom list accepts SI, SO, LS2, LS3, LS1R, LS2R, LS3R, SS2, and SS3. The prefixes + and - are optional.
terminal.iso2022_shifts | string | Tera Term | ISO2022ShiftFunction | on | -

# `ts.Title`, `ttset.c:713`. The window title before the host sends one.
#@ This setting sets the base window title. Sterna shows this title before a remote host gives a title.
terminal.title | string | Tera Term | Title | Tera Term | DLG_TERM_TITLE

# `ttset.c:663`. What the terminal sends when the host asks it who it is with
# ENQ (`0x05`) — `vtterm.c:1076` writes it with `CommBinaryOut`, so the bytes
# go out raw, with no CR translation and no local echo.
#
# **The value is a hex string, not the answer itself.** `Hex2Str`
# (`ttlib.c:406`) copies bytes through and reads `$` as the lead of a two-digit
# escape, so `Answerback=VT100$0D` is nine bytes ending in a CR. Three quirks
# come with it, all from the same loop: `ConvHexChar` answers **0** for a digit
# that is not hex, so `$ZZ` is a NUL; a `$` with fewer than two digits behind
# it borrows `'0'` for each one it is missing, so a trailing `$` is also a NUL
# and `$A` is `0xA0`; and the result is arbitrary bytes rather than text, which
# is why this is held as the file's own spelling and decoded at the point of
# use rather than stored decoded.
#
# It is also the one setting in this file another setting **overwrites**:
# `ttset.c:1132` replaces it outright with B Plus's five-byte activation string
# when `BPAuto=on`, a hundred lines after reading it, so a file that sets both
# loses this one without a word. See `transfer.bplus_auto`.
#@ This setting sets the bytes sent for an enquiry (ENQ) request. A dollar sign and two hexadecimal digits identify each non-text byte.
terminal.answerback | string | Tera Term | Answerback |  | -

# `ttset.c:1108`, `TF_BACKWRAP`. Whether a BS on the left margin steps back to
# the *previous* line rather than stopping dead. Off, `BackSpace`
# (`vtterm.c:662`) has an arm that does nothing at all; on, it moves to
# `CursorRightM` of the row above — the right *margin*, so a terminal with
# DECSLRM set lands inside the margins rather than at the last column.
#
# Only the arm that moves taps a BS into the log and the macro language's
# received-line buffer, so this key also decides whether a script's `wait` ever
# sees one at column zero.
#@ This setting moves the cursor to the right margin of the previous line when the host sends Backspace at the left margin. The off value prevents this movement.
terminal.back_wrap | bool | Tera Term | BackWrap | off | -

# `ttset.c:1343`, and it is read in two places that do not sound like the same
# setting. Off — which is how it ships — a tab is *like a printed character*:
# `Tab` (`vtterm.c:713`) takes a pending wrap first, so a tab arriving on a full
# line breaks the line before tabbing, and `CursorForwardTab` (`buffer.c:5228`)
# arms the pending wrap when it runs out of stops. On, both stop happening and a
# tab is only ever a cursor move, which is what a real VT does.
#
# CHT (`CSI Ps I`) is unaffected by the first half: it calls `CursorForwardTab`
# directly and never sees the wrap.
#@ This setting makes a Tab from the host move only the cursor. With the off value, a received Tab can wrap a full line like a printed character.
terminal.vt_compat_tab | bool | Tera Term | VTCompatTab | off | -

# `ttset.c:1717`, `ts.TabStopFlag`. Which sequences a *host* is allowed to move
# the tab stops with, as a comma list — `HTS7` is `ESC H`, `HTS8` is the 8-bit
# C1 at 0x88, `TBC0` is `CSI 0 g` and `TBC3` is `CSI 3 g`; `HTS` and `TBC` are
# each the pair. `on`/`all` and `off`/`none` assign the whole word.
#
# A `string` rather than a type of its own, for the same reason
# `terminal.iso2022_shifts` is one: it is a flag list and the parse lives beside
# the bits it names. Unlike that key, this one starts from `TABF_NONE` only in
# the *list* arm and the default applies whenever the value is absent **or**
# matches `on`.
#@ This setting selects the host commands that can change tab stops. The on and all values select all commands. The off and none values select no commands. HTS7 and HTS8 set a stop. TBC0 clears the current stop. TBC3 clears all stops.
terminal.tab_stop_modify | string | Tera Term | TabStopModifySequence | on | -

# `ttset.c:1756`, `TF_INVALIDDECRPSS`, and upstream's own comment is "(for
# testing)". `RequestStatusString` (`vtterm.c:4400`) flips the leading digit of
# the reply it was about to send, so a valid request answers `0$r` — "I do not

#@ This setting makes terminal status-string replies show the opposite success state. This setting is only for a test of host error handling.
terminal.invalid_decrqss | bool | Tera Term | UseInvalidDECRQSSResponse | off | -

# `ttset.c:1688`. The eight hex digits the tertiary DA (`CSI = c`) answers with,
# in a `DCS ! | … ST` (`vtterm.c:2829`).
#
# **Validated on read and the fallback is the default**: eight characters, every
# one a hex digit, upper-cased in place — anything else, including a nine-digit
# value, becomes `FFFFFFFF`. That is `ts.BSKey`'s shape rather than an enum's,
# so it is held as a string and checked at the point of use; a file keeps
# whatever it wrote, and the terminal answers with the valid form.
#@ This setting sets the terminal identifier for reports to hosts. The identifier has eight hexadecimal digits. Invalid values use FFFFFFFF.
terminal.uid | string | Tera Term | TerminalUID | FFFFFFFF | -

# `ttset.c:1711`, `TF_LOCKTUID`, and the default is **on** — so DECSTUI
# (`DCS ! { … ST`) is refused as shipped. `vtterm.c:4565` is the whole of it:

#@ This setting prevents a remote host from changing the terminal identifier. The off value lets the host assign that identifier.
terminal.lock_uid | bool | Tera Term | LockTUID | on | -

# `ttset.c:1101`, `TF_AUTOINVOKE`. Whether designating a character set into G0
# also invokes G0 into GL, so `ESC ( B` puts ASCII back on the wire's own bytes

#
# Two things about `ESCSBCSSelect` (`vtterm.c:1409`) that reading the name would

#@ This setting automatically activates a character set when the host designates it as the primary set. This can occur even when other ISO-2022 shifts are disabled.
terminal.auto_invoke | bool | Tera Term | AutoInvoke | off | -

# `ttset.c:1789`. The ceiling on the buffer an OSC or DCS string is collected

# --- encoding ---------------------------------------------------------------
#
# Sterna's terminal stream is UTF-8 and the roadmap explicitly defers the CJK
# decoder and IME depth. These rows still reproduce the existing file: they
# remain visible to the generated dialog and scripts, and will already be in
# the right shape if that scope is revived.

# `ttset.c:670` calls `GetKanjiCodeFromStr`, whose table is compared with
# case-sensitive `strcmp` (`ttlib_charset.cpp:147`). Empty and unknown values
# become UTF-8. Aliases are ordered with the spelling `GetKanjiCodeStr` writes

# `GetPrivateProfile*` with a thin wrapper, so the family of traps that applies

# lower-cases the value and compares it against a table — so it is

# **`[Sterna]`** again, and these two are only the *bar*: the buttons on it are
# a list, which no schema row can be, and they live in a `[Sterna Buttons]`
# section of their own (`tt-config/src/buttons.rs`).
#
# The whole visibility decision. An empty panel still shows its Add button, so
# checking this before any commands exist gives a direct route to the first.
#@ This setting shows the quick-button bar. You can change the buttons on this bar. An empty bar shows the Add button. You can use this button to make the first command.
window.quick_buttons | bool | Sterna | QuickButtons | on | -

# How wide the panel is, in pixels. **The bar is always down the right-hand
# side** — a terminal's rows are the scarce dimension, a window is usually far
# wider than the 80 columns it needs and exactly as tall as it can be, so a
# vertical bar costs nothing that is being used and the labels have room to be
# words rather than abbreviations.
#
# There was a `QuickButtonsArea` here until 0.5.4, naming one of the four
# edges. It went with the dock that made it possible: a dock separator takes
# its pixels out of the central widget, and the terminal beside it is fitted to
# whatever width is left in whole cells — so widening the panel resized the
# grid, and `Grid::resize` truncates every line it shortens, page and
# scrollback alike. The width below is the same gesture with the pixels coming
# out of the *window* instead, which is a thing a terminal can survive.
#
# **Zero means as wide as the buttons need**, and it is what ships. Pixels are
# the only honest unit for a panel of words — the same eight captions want a
# different number of them at every font size and every scale factor — so a
# shipped number would be a guess, and measuring is not. It also keeps a fresh
# install exactly where it was before this setting existed: the panel hugged
# its widest caption, and an empty one was as wide as its Add button.
#
# `int_clamp` rather than `int`: a number outside the range is somebody's typo,
# and clamping it keeps the panel on screen where taking the default would
# throw the width away and silently go back to measuring. The ceiling is a
# corruption guard and not the real limit — the real one is how far the window
# can grow before it leaves the screen, which only the window knows. The floor
# a panel is really held to is its own minimum, which depends on the captions
# and the font, so the window applies that too: validation at the boundary,
# the way `TerminalUID` is.
#@ This setting sets the width of the quick-button bar in pixels. Zero makes the bar as wide as its widest button. Sterna then changes the window width, and the terminal keeps its columns.
window.quick_buttons_width | int_clamp(0..2000) | Sterna | QuickButtonsWidth | 0 | -

# --- recent -----------------------------------------------------------------
#
# **`[Sterna]` is this program's own section and nothing upstream reads it.**
# It holds what the last connection was opened with, so the next New connection
# dialog opens where the last one left off — across restarts, which Tera Term
# does not do: upstream's host dialog is seeded from `ts` and `ts` only reaches
# the file through Setup > Save. See `docs/deviations.md`.
#
# Only the fields upstream has no key for are here. The serial *line* settings
# are `[Tera Term]`'s own `BaudRate`/`DataBit`/`Parity`/`StopBit`/`FlowCtrl`,
# which a connection updates in place — that is already what `setbaud` does
# (`Session::set_baud`, "a speed changed by a script must be the speed the
# dialog shows"), and a second copy of a speed would be a second answer to
# which one wins.
#
# Each record is meaningful only when its port or host is set: an empty
# `SerialPort` means nothing has been opened yet, and the dialog then shows
# what the settings say. A user who wants to forget a host clears the value
# here, which is why these are ordinary settings rather than hidden state.

# The device path, not a number: `ComPort` is upstream's and cannot spell
# `/dev/serial/by-id/usb-FTDI_…`. Written as the port was opened, so it is the
# `open_path` a stable symlink resolves from rather than the `ttyUSB<n>` that
# moves on replug.
#@ This setting stores the serial-device path that the connection dialog used last. Adapter renumbering changes a temporary name more frequently than a stable device link.
recent.serial_port | string | Sterna | SerialPort |  | -

# The hosts the New connection dialog offers, newest first, separated by `;`.
#
# Upstream keeps its list in a **section of its own** — `[Hosts]`, keys `Host1`
# to `Host500` (`ttset.c:3416`, `MAXHOSTLIST`) — which this schema cannot
# spell: it is a flat table of named settings, and an indexed family would be a
# second mechanism for one list. So this is one key, and **`Hosts` is not
# available as its name**: `ttset.c` reads that section itself, and a
# `[Sterna] Hosts` would be a second answer to a question their own Tera Term
# already asks. `tt-config/tests/upstream.rs` refuses the collision.
#
# Gated by `connection.history_list`, which is upstream's `HistoryList` and
# ships **off** — so nothing is remembered until the dialog's History box is
# ticked, and clearing this value forgets everything.
#@ This setting stores host entries for the New Connection dialog. This list puts the host from the last connection first. Host history must be active before Sterna updates this list.
recent.host_history | string | Sterna | HostHistory |  | -

# The SSH host the dialog was given — an alias out of `~/.ssh/config` as
# readily as a name, since that is what the dialog's combo box is filled from.
# Empty is the whole record's switch: nothing remembered, so the dialog opens
# as it does on a fresh install.
#@ This setting stores the last SSH host or SSH configuration alias entered in the connection dialog. An empty value removes the SSH record.
recent.ssh_host | string | Sterna | SshHost |  | -

# The user, where one was typed. Empty means "whatever `~/.ssh/config` says",
# which is not the same as an empty user name — so the absence round-trips
# rather than being resolved on the way in.
#@ This setting stores the last entered SSH user. An empty value does not identify an SSH user. The SSH configuration then selects the user.
recent.ssh_user | string | Sterna | SshUser |  | -

# The port, where one was asked for. Zero is the same kind of absence as an
# empty user: it leaves the choice to `~/.ssh/config` and, failing that, to 22.
#@ This setting stores the last entered SSH port. Zero does not identify an SSH port. The SSH configuration then selects the port. Without an SSH configuration port, SSH uses port 22.
recent.ssh_port | uint16 | Sterna | SshPort | 0 | -

# The private key the dialog was given, if it was given one. `~/.ssh/config`
# and the agent are consulted regardless, so this is an addition to them.
#@ This setting stores the last selected SSH private key. Sterna also refers to the SSH configuration and the SSH agent.
recent.ssh_identity | string | Sterna | SshIdentity |  | -

# The pre-2020 algorithm switch, which is a property of the equipment at the
# far end rather than a preference — a console server that needed it once needs
# it every time, and that is the whole reason this record exists.
#@ This setting stores the pre-2020 algorithm selection for the last SSH host. This selection is applicable only to equipment that cannot use modern algorithms.
recent.ssh_legacy | bool | Sterna | SshLegacy | off | -

# The telnet host. Empty is this record's switch, as `SshHost` is its own.
#@ This setting stores the last Telnet host entered in the connection dialog. An empty value removes the Telnet record.
recent.telnet_host | string | Sterna | TelnetHost |  | -

# The telnet port, kept separate from `[Tera Term] TCPPort` deliberately: that
# one is also what a bare host name on the command line opens, so remembering a
# console server's per-line port there would move an SSH connection to it.
#@ This setting stores the last Telnet port. It does not change the general network port for other connection types.
recent.telnet_port | uint16 | Sterna | TelnetPort | 23 | -

# Which of the four framing/burst combinations was used (`TelnetMode::of`).
# `auto` is the shipped one: data until the first `IAC`, telnet after it.
#@ This setting stores the last Telnet mode. Negotiate starts Telnet immediately. Framed escapes Telnet bytes without startup negotiation. Auto waits for 0xFF. Raw changes no bytes.
recent.telnet_mode | enum(auto=Auto,negotiate=Negotiate,framed=Framed,raw=Raw) | Sterna | TelnetMode | auto | -

# The connections that were actually opened, newest first, at most ten,
# separated by `;`. The nine keys above remember *one* of each kind, which is
# what seeds the connect dialog; this is the list the toolbar offers, and it is
# a different thing — a list has to say which kind each entry is and carry the
# parameters that entry was opened with, or picking one is a guess.
#
# Each record is written the way its destination is spoken:
#
#     serial:<path>?baud=115200&bits=8&parity=none&stop=1&flow=none
#     ssh://[user@]host[:port][?identity=<path>][&legacy=1]
#     telnet://host[:port][?mode=auto]
#     shell:
#
# and holds exactly the fields the connect dialog asks for. Everything else a
# connection needs is a setting, and a setting that changes should change for a
# remembered connection too — pinning a whole `TtSerialParams` here would
# freeze answers the settings file is supposed to own. `%` and the six
# delimiters are percent-encoded; a record that does not parse is dropped
# rather than repaired, because this file is hand-edited.
#@ This setting stores a maximum of ten recent connections for the toolbar. Each entry keeps its connection type and the parameters necessary to open it again.
recent.connections | string | Sterna | Recent |  | -

# Whether opening a connection adds it to that list. On, unlike upstream's
# `HistoryList` — a bar whose list is empty until a preference is found and
# ticked is a bar that does nothing on the day it is installed. Off stops
# recording only: what is already there stays on offer, because hiding a list
# somebody can no longer add to is taking away the entries *and* the way to
# reach them. The bar's own Forget item is what removes them.
#@ This setting adds opened connections to the recent list on the toolbar. The off value prevents new entries. Previous entries stay available.
recent.remember | bool | Sterna | RememberConnections | on | -

# The directory the last log was written to, so the log dialog opens where the
# last one landed rather than where the settings file was pointing when it was
# written. Upstream has no key for this and does not remember: `GetTermLogDir`
# answers the same three-way question every time (`log.default_path`, then
# `transfer.file_dir`, then the per-user directory).
#
# **Consulted only when `log.default_path` is empty.** A configured log
# directory is somebody saying where logs go, and a remembered one that
# silently overrode it would make the setting look broken. What this replaces
# is the *rest* of `GetTermLogDir`'s chain — the file-transfer directory, then
# a per-user directory nobody chose — which is where an unconfigured log lands
# and is not a place anyone would look twice.
#
# Only the log dialog writes it: a `/L=` path or an auto-started template is a
# script's choice and must not retarget the next log a person opens. It is
# recorded whether or not it is currently being consulted, so clearing
# `LogDefaultPath` later falls back to somewhere real.
#@ This setting stores the directory selected in the Log dialog. Without a default log directory, Sterna uses this directory for the next log.
recent.log_dir | string | Sterna | LogDir |  | -

# What was last typed into the find bar, newest first, separated by `;`.
#
# The same shape as `recent.host_history` above and for the same reason: a list
# is not something a flat table of named settings can hold, and an indexed
# family of keys would be a second mechanism for one. `%` and `;` are
# percent-encoded, so a pattern containing either survives the round trip —
# which matters more here than it does for a host name, since `;` is a
# perfectly ordinary thing to search a console log for.
#
# Twelve are kept. Clearing the value forgets the lot, and there is no switch:
# a search box with no memory of the last thing you searched for is a search
# box you retype into, and nothing here reaches the network or the disk the way
# a remembered connection does.
#@ This setting keeps the last search patterns for the find bar list. Sterna keeps a maximum of twelve patterns. An empty value erases the list.
recent.find_history | string | Sterna | FindHistory |  | -

# The three boxes on the find bar, as they were left.
#
# Settings rather than window state because they change what a pattern *means*,
# so somebody who works in regular expressions should not have to say so again
# every time they open the bar. They live beside the remembered log directory
# for the same reason it does: this is where the answer to "how was this last
# set" goes.
#@ This setting keeps the last value of the Case option in the find bar. With the on value, a search finds only text with the same uppercase and lowercase letters as the pattern.
recent.find_case | bool | Sterna | FindCase | off | -

# Whether a match has to have a word boundary at each end.
#@ This setting keeps the last value of the Whole word option in the find bar. With the on value, a search finds the pattern only when a word boundary is at each end.
recent.find_whole_word | bool | Sterna | FindWholeWord | off | -

# Whether the pattern is a regular expression rather than text to be found.
# Off, because a console is full of `.` and `[` and somebody searching for an
# IP address should get the one they typed.
#@ This setting keeps the last value of the Regex option in the find bar. With the on value, a search uses the pattern as a regular expression. With the off value, a search finds the same characters as the pattern.
recent.find_regex | bool | Sterna | FindRegex | off | -

# --- updates ----------------------------------------------------------------
#
# **`[Sterna]` again**: upstream ships no updater, so there is no key to be
# compatible with. Sterna does ship one, and a signed release nobody hears
# about is a security fix nobody installs — which is why the startup check is
# on rather than off. It contacts the release server and nothing else, and the
# manifest is verified before its version, URL or size is trusted, exactly as
# the Help > Check for Updates path is. Turning this off leaves that button
# working: it is a schedule, not a switch on the feature.

# Whether starting Sterna may look for a new release. On, so an installed
# terminal learns about a signed update without anyone remembering to ask.
#@ This setting does a check for a signed Sterna update when the application starts. Manual update checks stay available with the off value.
updates.check_on_startup | bool | Sterna | CheckUpdatesOnStartup | on | -

# When the last look happened, as ISO-8601 UTC — the "once a day" half of it.
# Written when a check *starts*, so a release server that cannot be reached
# costs one request a day rather than one per launch. Empty means never, which
# is also what clearing it by hand means: check at the next start. Anything
# unparsable, and anything in the future — a clock moved back, an edited file —
# reads the same way, because the alternative is a terminal that never looks
# again.
#@ This setting records the start time of the last update check in Coordinated Universal Time. Empty, invalid, or future values let Sterna do one more check at the next start.
updates.last_check | string | Sterna | LastUpdateCheck |  | -
